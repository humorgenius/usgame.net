# 内容入库规范（Content Ingest Spec）

> 目的：用最少的人工，把 `.doc` 成稿变成可构建的 MDX + 优化后的图片。
> 现状：**73 篇中文 `.doc`**（`D:\【建立网站】\GTA6\GTA6游戏图文内容\`）+ 你说已有对应英文版。
> 你只需要做第 2 节那两件事，其余全部由脚本完成。

---

## 1. 已探明的源文件情况（不用你改）

| 项 | 实测结论 |
|---|---|
| 数量 | **73 个** `.doc`（不是 80） |
| 格式 | 全部是 **legacy `.doc`（OLE2）**，不是 `.docx` |
| 体积 | 0.04–18MB，大的里面**嵌了图**（如「全部角色背景一览」15MB、「我们还有 6 个最关心的问题」18MB） |
| 段落样式 | 基本全是 `Normal`，少量 `Heading3` —— **没有可靠的标题层级**，章节结构靠语义推断 |
| 内嵌 HTML | 文里写着**转义过的** `<iframe …></iframe>` 文本（预告片嵌入），导入时必须还原成真嵌入 |
| 转换器 | 本机已有 **LibreOffice**（`C:\Program Files\LibreOffice\program\soffice.exe`），实测 2.7 秒/篇 |
| 依赖 | 不需要 `python-docx`；直接解析 `word/document.xml` 与 `word/media/*` |

### ★ 关键发现：中英文在**同一个文件**里

抽样 3 篇（通缉等级改动 / 城市街区 / 预告片细节解析）**全部**是这个结构：

```
《GTA6》通缉等级改动：从五星到六星的全面进化     ← Heading3，中文标题
  正文…
  1. 最高等级回归六星                              ← Heading3，中文章节
  …
GTA6 Wanted Level Changes: A Full Evolution …   ← Heading3，英文标题（拉丁为主）
  Body…
  1. The Ceiling Returns to Six Stars             ← Heading3，英文章节
  …
```

实测对应关系（通缉等级改动）：

| | ZH | EN |
|---|---|---|
| 章节数 | 9 | 9 |
| 表格数 | 2 | 2 |
| 图片位 | 4 | 4 |
| 章节顺序 | 一一对应 | 一一对应 |

**所以「中英配对」这件事不存在**——切分点 = 第一个以拉丁字母为主的 Heading3（CJK 占比 < 5%）。
两个语言的章节数 / 表格数 / 图片位必须一一相等，不等就说明稿子有问题（脚本会报错，见第 4 节）。

**导入流水线**（我来做，你无需操作）：

```
.doc ──soffice──▶ .docx ──unzip──┬─ word/document.xml  → 结构化 MDX 正文（中英各一份）
                                 └─ word/media/*       → 图片，转 WebP + srcset
```

规则：
- `Heading3` → `##`；`Normal` 段落按语义推断 `###`（原文基本没有更细的层级）。
- 转义的 `<iframe>` → 还原成 `youtube-nocookie` 真嵌入组件。
- 图片按锚点位置就近插入，自动补 `alt`，并记录来源以便你替换。
- 连续 `- ` 段落 → `<ul>`；以引号开头的短段 → `<blockquote>`。
- **加粗**（`<w:b/>`）与*斜体*会保留，原文的强调不会丢。
- 正文中的**相对时间词**（"目前""预计""即将"）会被标红列成清单给你确认 —— 内容站最容易被挑的就是时效性错误。

## 4. 构建硬性校验（已实现 + 待实现）

已实现（`scripts/build-content-page.py` 内置，跑通即打印"结构门禁: 通过"）：

| 门禁 | 规则 | 失败后果 |
|---|---|---|
| 结构平行 | 中英**章节数 / 表格数 / 图片位**必须一一相等 | 打印差异清单（实测 9/2/4 == 9/2/4 通过） |
| 标题可嵌入 | 标题不得含 `" & < >`（否则会破坏属性与 JSON-LD） | 打印告警 |
| 占位符 | 模板占位符必须全部被替换 | 打印未替换清单 |
| 中英切分 | 必须能找到拉丁为主的 Heading3 作为切分点 | 直接报错退出 |

待实现（阶段 4 的门禁脚本）：

| 门禁 | 规则 | 失败后果 |
|---|---|---|
| `check-i18n` | 每个 `translationKey` 必须**中英各有一条** | **构建失败** |
| `check-seo` | title / description 长度、canonical、hreflang 三向互指 | 构建失败 |
| `check-links` | 站内死链、重复 slug | 构建失败 |
| `check-freshness` | 正文里的相对时间词清单 | 打印待确认列表 |
| `check-images` | 每张图有 `alt` / 尺寸 / 懒加载；单图 < 350KB | 构建失败 |

## 5. 一个必须提前说清的问题

你现在的中文稿里**写死了具体事实**（发售日 2026-11-19、价格、平台、评级 Mature 17+、销量预测）。
这些是**会过期**的。英文版如果是同一时间写的，两版会**同时过期**。

建议：
- 凡是"官方已确认"的事实，每条在 frontmatter 里记 `source` + `verifiedAt`；
- 首发前我跑一遍时效性复核清单，逐条标"仍有效 / 已变更 / 已作废"给你过。

这是内容站唯一会持续掉分的地方，也是 AdSense 复审时会看的。
